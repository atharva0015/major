# EXTENSION_VISION_LLM -- benchmark results and keep-or-drop

Generated by `make bench-vision` (see `benchmark/reports/vision.md` for the
machine-readable numbers). Method: stdlib deterministic visual fingerprints
(`healing/matching/vision.py`, versioned `vision-0.1.0`) shortlist candidates
by cosine similarity; a multimodal LLM (`healing/matching/llm_attempt.py`)
is consulted only when embeddings are ambiguous, must emit structured JSON
(selector plus evidence), and the selector is re-validated against the real
DOM before use. All external calls masked via `healing/security/masking.py`;
self-hosted endpoints via `policy.yaml vision_llm` (httpx, already a
dependency). Features OFF by default, enabled per application.

## Results (24 UI cases, seed 42)

- Vision standalone top-1: 15/15 healable cases ranked correctly.
- Vision ambiguous: 15/15 -- fingerprints are too coarse to separate
  same-form buttons (shared tag, classes, text shape), so the shortlist
  margin never clears and the ladder correctly declines to pick.
- Full ladder with vision on + 4th attempt allowed: wins 1:15, 2:0, 3:0, 4:0.
- LLM disabled abstains on every call; even an oracle LLM (perfect
  proposals) would add 0 marginal wins -- the ladder already won at attempt 1.
- Cost: attempts 1-2 healed 15/15 at ~15.0; attempts 3-4 healed 0/15 while
  each firing would cost vision_max_cost (1.0) + llm_max_cost (2.0).

## Recommendation: DROP (leave disabled)

Attempts 3 and 4 do not beat attempts 1 and 2 per unit cost -- they add
zero marginal heals at nonzero configured cost. The code stays as a
tested, default-off fallback for genuinely visual drift (canvas-rendered
controls, reskins beyond class renames) where DOM locators carry no
signal. Revisit only with (a) real screenshots and (b) a benchmark where
attempts 1-2 demonstrably fail.
